Are there secrets in the code?

IN LOBEHUB

High

A ready-made login-service file holds a real private key that signs logins, plus admin / pswd123:

docker-compose/production/
grafana/init_data.json

Every default install also shares one database password.

Check

Keys, tokens and passwords in files, including “example” files, and passwords every install shares.

Why it matters

Anyone can sign in or forge logins on a server that uses them unchanged. Once pushed, a secret stays in the history.

Stay safe

Never reuse sample keys or passwords; make your own. Before we push our code, ask Claude to scan for secrets.

Before you fork

This is the same mistake the GitHub 101 guide warns us about in Stop 8, made by a large, professional project. Rated High because anyone who uses these files unchanged is open to forged logins or sign-in with known passwords: the setup script regenerates some secrets but never the database password. It cuts both ways: check what others left in their code, and check our own code before we push it. Deleting a secret in a later commit doesn’t help, because it stays in the history and in every copy; it must be replaced. Keep GitHub push protection on.
